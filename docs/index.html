OntoGSN is an ontology for enabling users to manage (i.e., create, maintain, align, evaluate, explain and display) GSN assurance cases semantically.

What it gives you

  • Graph-native cases

    Store and query assurance cases as graph data. Stored SPARQL queries answer common questions about a case.

  • Readable and visual

    A human-readable representation of the domain that tools can draw as a tree.

  • One store for everything

    Link claims and evidence to data, documents and code in one place.

  • Logic-based checks

    SWRL rules for reasoners, the same rules as SPARQL updates for stores without one, and SHACL shapes for validating case data.

  • Ready for new methods

    A foundation for advanced methods such as GraphRAG.

  • Open tooling

    An active, mostly open-source ecosystem of editors, stores and reasoners.

Grounded in the standard

Every term is sourced from the GSN Community Standard v3, across its five sections: core GSN and the argument pattern, modular, confidence and dialectic extensions. A provenance record traces each axiom to the passage of the standard behind it, and records the reasoning.

The ontology acts as a "translator" (i.e., middleware) between a system and its assurance case, and as a validator for the rules of the standard. You do not need to write a separate interface for each system, or update the assurance case by hand. Because the ontology carries the updates, you can follow the system's design, implementation, testing and runtime from the assurance case tree itself. This suits auditors, safety and security engineers, and other supervisory or monitoring roles.
